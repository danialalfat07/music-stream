================================================================

LOKASI: public/app.js baris 4245 (fungsi) ; blok durasi baris 4257-4291.

Kode ekstraksi durasi (baris 4257-4291):
----------------------------------------------------------------
  const raw =
    it.duration != null && it.duration !== ''
      ? it.duration
      : it.dur != null && it.dur !== ''
        ? it.dur
        : it.lengthSeconds != null
          ? it.lengthSeconds
          : it.length;
  let secs = parseDurationSec(raw);
  if (!(secs >= 1 && secs <= 43200)) secs = durationFromSubtitle(it.subtitle);
  if (!(secs >= 1 && secs <= 43200) && it.videoId) {
    try {
      const st = Library.stats[it.videoId];
      if (st && st.duration) secs = parseDurationSec(st.duration);
    } catch {}
  }
  let label = '';
  if (secs >= 1 && secs <= 43200) label = fmtTime(secs);
  if (!label) {
    const live =
      (it.qi === Player.index &&
        ((Player.native && Player.native.dur && Number(Player.native.dur)) ||
          (Player.audio && Number(Player.audio.duration)))) ||
      0;
    if (live > 0 && live <= 43200) label = fmtTime(live);
  }
  const empty = !label;
  return `<span class="tdur${empty ? ' is-empty' : ''}">${esc(empty ? '--:--' : label)}</span>`;
----------------------------------------------------------------

Field yang dibaca: `it.duration`, `it.dur`, `it.lengthSeconds`, `it.length`.

Fallback yang ada:
  1) `parseDurationSec(raw)` dari field eksplisit.
  2) `durationFromSubtitle(it.subtitle)` — TIDAK PERNAH KENA di Recently
     Played, karena `pushHistory` sudah MEMBUANG segmen durasi dari
     subtitle saat menyimpan (baris 743-746).
  3) `Library.stats[it.videoId].duration` — SELALU GAGAL, karena `stats`
     tidak pernah menyimpan field `duration` (baris 750-765).
  4) Durasi engine hidup — hanya bila `it.qi === Player.index`. Di
     Recently Played, `it.qi` TIDAK PERNAH di-set (bandingkan baris
     5317 yang hanya pass `artist`+`subtitle`), sehingga `it.qi ===
     Player.index` = `undefined === number` = false -> label tetap kosong.

MENGAPA BERUJUNG "--:--":
  - Bukan karena nama field beda (bukan `durationMs` vs `duration`).
  - Bukan karena `it` benar-benar kosong.
  - Penyebabnya: record history TIDAK punya `duration` valid (Write
    gagal), DAN semua fallback DISPLAY dirancang untuk kondisi yang
    tidak terpenuhi:
      * subtitle cadangan sudah dibersihkan di Write,
      * `stats.duration` tidak pernah disimpan,
      * `it.qi` tidak diberikan untuk baris Recently Played,
      * engine live belum siap saat record baru (jalur native).

KESIMPULAN A3: DISPLAY memburuk oleh Write yang menyimpan data tanpa
durasi + membersihkan subtitle. `trackRowHTML` tidak salah sendiri,
tetapi fallback-nya tidak efektif untuk Recently Played.

5. KESIMPULAN (DI MANA BUGNYA)
================================================================
Bug UTAMA ada di WRITE PATH, diperparah di DISPLAY PATH.

Rantai putusnya:

  [API search] item.duration sering undefined
        (server.js: hanya diisi dari fixedColumn; search tak punya)
  -> subtitle memuat durasi sbg teks ("... • 3.22")
  -> [WRITE] pushHistory menerima song tanpa duration
  -> fallback #2 (durationFromSubtitle) kadang menolong, TAPI
  -> [WRITE] records disimpan SETELAH subtitle dibersihkan (durasi dibuang)
  -> jika fallback gagal, rec.duration TIDAK ADA sama sekali
  -> [READ] viewSearch spread ...s (benar) tapi duration memang tidak ada
  -> [DISPLAY] trackRowHTML: field kosong, subtitle sudah bersih,
     stats tak punya duration, it.qi tak di-set -> "--:--"

READ PATH = BERSIH (bukan sumber bug).
WRITE PATH  = SUMBER BUG (durasi tidak tersimpan / hilang permanen).
DISPLAY PATH = memperburuk (fallback tidak efektif untuk Recently Played).

Kasus khusus yang PASTI menghasilkan "--:--":
  a) Jalur NATIVE (VisionOS): `pushHistory` dipanggil SEGERA setelah
     `startNativeTrack` (baris 2565-2566) -> engine belum resolve durasi.
  b) Record lama yang tersimpan sebelum perbaikan sebelumnya.
  c) `stats` tidak pernah menyimpan `duration` -> fallback #4 mati.
  d) `it.qi` tak diberikan di Recently Played -> fallback live mati.

6. REKOMENDASI FIX (JANGAN DIEKSEKUSI — ini hanya usulan)
================================================================

R1. SIMPAN `duration` KE `Library.stats` (perbaikan kecil, berdampak
    besar). Di `pushHistory` (baris 750-765), saat membuat/memperbarui
    `st[k]`, tambahkan:
        st[k].duration = dur ? normalizeDuration(dur) : (st[k].duration || '');
    Alasan: fallback #4 di `trackRowHTML` (baris 4273-4277) jadi hidup,
    sekaligus `durationFromSubtitle` tidak lagi satu-satunya jaring.
    (Namun ini tetap bergantung pada `dur` valid — lihat R2.)

R2. PERBAIKI URUTAN WRITE: jangan bersihkan subtitle SEBELUM durasi
    benar-benar didapat, atau simpan durasi mentah lebih dulu.
    Konkret: saat `pushHistory` menyimpan `rec.subtitle` yang sudah
    dibersihkan, SERTAKAN juga segmen durasi yang sudah diekstrak ke
    `rec.duration`. Bila `dur` gagal didapat, JANGAN menghapus segmen
    durasi dari subtitle (biarkan `durationFromSubtitle` bisa
    memulihkannya di render). Ini menghilangkan sumber "--:--" permanen.

R3. TUNDA `pushHistory` DI JALUR NATIVE sampai durasi tersedia.
    Di baris 2565-2566, panggil `pushHistory` setelah event durasi
    native tiba (mis. saat `Player.native.dur > 0`), bukan segera
    setelah `startNativeTrack`. Alternatif: simpan lewat mekanisme
    "backfill" — perbarui record history saat durasi engine pertama
    kali diketahui. (Backfill sudah ada sebagian; pastikan menulis
    ke record `hist` yang benar, bukan hanya `rec` lokal.)

R4. SUPLAI `it.qi` (atau penanda "isNowPlaying") saat me-render Recently
    Played di `viewSearch` (baris 5317) bila ingin fallback durasi
    engine hidup untuk lagu yang sedang diputar. Alternatif lebih bersih:
    jangan andalkan durasi engine untuk list; andalkan `st.duration`.

R5. PERTIMBANGKAN ambil durasi dari API lain saat search. Karena
    `server.js parseListItem` hanya mengisi `duration` dari fixedColumn,
    fallback server-side (mis. bila fixedColumn tidak ada, ambil dari
    segmen flex terakhir yang cocok pola durasi) akan membuat
    `it.duration` selalu terisi. Ini patch di server.js (di luar fokus
    app.js, jadi hanya catatan).

R6. PERBAIKI `normalizeSong` (baris 4172-4175) agar IKUT menormalkan
    `duration` (mis. `duration: normalizeDuration(s.duration)`) sehingga
    semua objek yang lewat playSong konsisten bersih.

REKOMENDASI PRIORITAS: R1 + R2 (perbaikan terkecil, menyentuh hanya
`pushHistory`) kemungkinan besar sudah menghilangkan "--:--" karena
menghidupkan kembali fallback stats dan mencegah penghapusan durasi
yang belum tersimpan. R3 untuk kasus jalur native.
