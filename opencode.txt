================================================================
KONTEKS MASALAH
================================================================
Saat ini, cache lagu "Complete" sudah memiliki limit (bisa diatur
lewat Settings, misal maksimal 50 lagu). Ini sudah BENAR.

NAMUN, cache lagu "Incomplete" (file yang sedang di-download /
di-stream parsial) TIDAK MEMILIKI LIMIT. Bisa menumpuk sampai 300 file
dan memakan storage.

Selain itu, file incomplete ini disimpan di direktori Cache OS
(Context.getCacheDir), yang mana OS Android bisa menghapusnya
sewaktu-waktu secara sepihak.

EKSPEKTASI:
1. Limit file incomplete maksimal 10 file. Jika lebih, hapus file
   incomplete paling lama.
2. Pindahkan direktori penyimpanan file incomplete dari getCacheDir()
   ke getFilesDir() (folder data aplikasi permanen yang tidak 
   dihapus OS).

================================================================
TUGAS IMPLEMENTASI
================================================================

A1. INVESTIGASI (Wajib Dilakukan Dulu)
    - Grep `getCacheDir` dan `getFilesDir` di seluruh folder
      android/app/src/main/java/com/dnialify/musicstream/.
    - Cari class yang menangani file parsial / incomplete (biasanya
      SongCache.java, GrowingFileDataSource.java, atau NativeAudioEngine.java).
    - Laporkan bagaimana file incomplete diberi nama dan disimpan
      (apakah berekstensi .part, .tmp, atau di folder khusus?).
    - Cari di mana logika eviction/limit untuk file COMPLETE berada
      (sebagai referensi cara menghapus file).

A2. PINDAH DIREKTORI (Files Dir)
    - Ubah path untuk file incomplete. Alih-alih menggunakan 
      `context.getCacheDir()`, gunakan sub-folder di dalam 
      `context.getFilesDir()` (misal: `new File(context.getFilesDir(), "incomplete_cache")`).
    - Pastikan folder tersebut dibuat (mkdirs) jika belum ada.
    - Pastikan class yang membaca file (seperti GrowingFileDataSource) 
      menunjuk ke path yang BARU ini, bukan path cache lama.

A3. IMPLEMENTASI LIMIT 10 FILE INCOMPLETE
    - Setiap kali sistem membuat/menyimpan file incomplete BARU, 
      lakukan pengecekan.
    - Jika jumlah file di folder `incomplete_cache` > 10, cari file
      yang `lastModified()`-nya paling lama, lalu hapus file tersebut.
    - Pastikan file yang SEDANG DIPUTAR saat ini (active playing)
      TIDAK dihapus oleh proses eviction ini.
