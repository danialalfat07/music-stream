KONTEKS - 3 ISSUE UI DI SEARCH PAGE
================================================================

Aplikasi: DBOT / music-stream
Access: bottom bar -> tombol Search -> masuk Search Page

ISSUE 1 - Recently Played: durasi tampil "--:--"
  Di section Recently Played (bagian atas Search Page),
  setiap item menampilkan durasi "--:--" (bukan durasi
  sebenarnya). Seharusnya tampil seperti "3:45" atau
  "1:02:30".

ISSUE 2 - Searchbox: ada 2 tombol X (clear)
  Di search input ada 2 tombol clear (X). Keduanya
  berfungsi menghapus teks. User ingin:
  - PERTAHANKAN tombol X di pojok KANAN
  - HAPUS tombol X di sisi KIRI
  (Jangan menebak mana kiri-kanan tanpa cek kode. Kalau
   tidak yakin, laporkan keduanya dulu di investigation.)

ISSUE 3 - Search Results: layout baris
  Setiap hasil pencarian (tiap lagu) punya layout:
  - Sebelah KIRI: artwork (thumbnail)
  - Sebelah KANAN artwork: 2 baris teks
    - Baris ATAS: judul lagu
    - Baris BAWAH: artist, view count, dan DURASI
      (durasi tampil "--:--" juga, sama bug dengan Issue 1)

  User ingin:
  - HAPUS durasi dari baris bawah
  - PINDAHKAN durasi ke UJUNG KANAN baris (kolom kanan,
    rata kanan vertikal center, format seperti "3:45")
  - Baris bawah hanya berisi: artist, view count
  - Bug durasi "--:--" juga harus diperbaiki (kalau
    root cause sama dengan Issue 1, fix sekali jalan)

FASE 2 - FIX
================================================================

F2.1 - FIX DURASI (Issue 1 + Issue 3)
    Berdasarkan I4, terapkan fix yang sesuai:

    KASUS A - Data ada tapi formatting salah:
      - Pakai / perbaiki helper formatDuration yang ada
      - Pastikan detik -> "M:SS" atau "H:MM:SS"
      - Terapkan di Recently Played DAN Search Results

    KASUS B - Data duration tidak ada di recently played:
      - Saat user play lagu, simpan duration ke payload
        recently played di localStorage
      - Saat render recently played, baca dari payload
      - Backward-compatible: kalau record lama tidak
        punya duration, biarkan "--:--" atau kosong
        (jangan crash)

    KASUS C - Nama field beda:
      - Mapping field yang benar (misal durationMs /
        lengthSeconds / dll) -> convert ke detik
      - Terapkan di kedua tempat

    Kalau root cause > 1 (misal recently played butuh
    fix di penyimpanan, search results butuh fix di
    format), kerjakan keduanya.

    JANGAN ubah data lama di localStorage user secara
    massal (jangan migrate). Cukup handle gracefully
    kalau record lama tidak ada duration.

F2.2 - HAPUS 1 TOMBOL X (Issue 2)
    Berdasarkan I2:
    - Identifikasi tombol X di KIRI (yang harus dihapus)
    - Hapus rendering / hide dengan display:none / hapus
      elemen dari DOM
    - Pastikan tombol X di KANAN tetap berfungsi
      (clear input + re-trigger search atau sesuai
      perilaku existing)
    - Kalau ada handler duplikat, jangan sampai kehapus
      keduanya

    Kalau ternyata ada 2 tombol X yang punya class sama
    dan sulit dibedakan di CSS, bisa pakai selector
    :first-child / :last-child di parent. Tapi
    prefer hapus dari HTML/JS supaya DOM bersih.

    JANGAN hapus tombol X yang kanan.

F2.3 - PINDAHKAN DURASI KE UJUNG KANAN (Issue 3)
    Berdasarkan I3:
    - Hapus durasi dari baris bawah (baris artist + view
      count)
    - Tambah elemen durasi baru di ujung kanan baris:
      - Posisi: right-aligned
      - Vertikal: center dengan artwork / row
      - Format: "M:SS" atau "H:MM:SS" (dari F2.1)
      - Class baru misal `.result-duration` atau pakai
        yang sudah ada
    - Update CSS di public/styles.css:
      - Pastikan row pakai flexbox (kalau belum)
      - `.result-duration` di-push ke kanan
        (margin-left: auto atau flex-end di container)
      - Pastikan tidak overflow di layar kecil

    Kalau baris bawah artist + view count jadi terlalu
    panjang karena durasi dihapus, biarkan - jangan
