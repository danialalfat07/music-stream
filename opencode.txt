## MediaSession

One session only:

```java
private MediaSessionCompat mediaSession;
```

Created in `PlaybackService.onCreate()`:

```java
mediaSession = new MediaSessionCompat(this, "MusicStreamSession");
mediaSession.setFlags(MediaSessionCompat.FLAG_HANDLES_MEDIA_BUTTONS
        | MediaSessionCompat.FLAG_HANDLES_TRANSPORT_CONTROLS);
```

Notification uses same session token:

```java
.setStyle(new androidx.media.app.NotificationCompat.MediaStyle()
        .setMediaSession(mediaSession.getSessionToken())
        .setShowActionsInCompactView(0, 1, 2))
```

This gives system/lockscreen media controls without creating second session architecture. Session metadata and playback state come from WebView bridge state.

## Foreground Service

```java
public class PlaybackService extends Service
```

Service manifest entry remains media playback foreground service:

```xml
<service
    android:name=".PlaybackService"
    android:enabled="true"
    android:exported="false"
    android:foregroundServiceType="mediaPlayback" />
```

`startForeground(NOTIFICATION_ID, notification)` remains notification promotion path. `onTaskRemoved()` does not stop service. `onDestroy()` releases MediaSession only when service itself is destroyed, not when paused notification is dismissed.

## Action Routing

### Previous

```text
Notification PendingIntent action "prev"
  -> PlaybackService.onStartCommand()
  -> sendToWebView("if(window.prevTrack) prevTrack();")
  -> WebView prevTrack()
```

### Play/Pause

```text
Notification PendingIntent action "toggle"
  -> PlaybackService.onStartCommand()
  -> sendToWebView("if(window.togglePlay) togglePlay();")
  -> WebView togglePlay()
```

MediaSession callbacks use same WebView route:

```java
@Override public void onPlay() {
    sendToWebView("if(window.togglePlay) togglePlay();");
}

@Override public void onPause() {
    sendToWebView("if(window.togglePlay) togglePlay();");
}
```

WebView remains source of truth. Native callback does not directly play/pause native audio.

### Next

```text
Notification PendingIntent action "next"
  -> PlaybackService.onStartCommand()
  -> sendToWebView("if(window.nextTrack) nextTrack(false);")
  -> WebView nextTrack(false)
```

## Playback Guardrails

Removed native playback implementation from current Android service:

- No `ExoPlayer` import or instance.
- No Media3 dependency in `android/app/build.gradle`.
- No `MediaSessionService` inheritance.
- No `Media3` manifest intent filter.
- No `VIDEO_URL` passed to native player.
- No dummy `Uri`.
- No Opus/MP3 extraction.
- No second playback engine.

WebView `<video src="VIDEO_URL">` remains playback engine.

Preserved:

- Brave document-start JavaScript injection.
- `dispatchWindowVisibilityChanged(View.VISIBLE)` patch.
- Existing Capacitor `BridgeWebViewClient`.
- Existing WebView background playback behavior.

`public/app.js` now treats `NativePlayback` as notification/control bridge only:

```js
// NativePlayback is notification/control bridge; WebView remains playback engine.
Player.native = false;
```

Removed visibility-time handoff to native playback. WebView is not paused and transferred to another engine when app hides.

## Lyrics Bridge

Java bridge remains in `MainActivity.PlaybackBridge`:

```java
@JavascriptInterface
public void updateLyrics(String prev, String current, String next) {
    PlaybackService.updateLyricsStatic(MainActivity.this, prev, current, next);
}
```

Java stores three WebView values:

```java
private String previousLyric = "";
private String currentLyric = "";
private String nextLyric = "";
```

`setViews()` binds them into collapsed and expanded `RemoteViews`. Empty lyric rows become `View.GONE`. Current lyric keeps larger/bold XML styling.

JavaScript source remains `public/app.js`:

```js
window.NativePlayback.updateLyrics(prev || "", cur || "", next || "");
```

Lyrics update when `updateLyricHighlight()` changes current line and when lyrics load.

## Artwork Handling

WebView sends thumbnail URL in `pushNativeState()`:

```js
const artwork = s.thumbnail || '';
window.NativePlayback.updateWebViewState(
  title, artist, artwork, !!playing, posMs, durMs
);
```

Service loads artwork off main thread with `BitmapFactory`. Loaded bitmap feeds:

- collapsed RemoteViews artwork
- expanded RemoteViews artwork
- `MediaMetadataCompat.METADATA_KEY_ALBUM_ART`
- `MediaMetadataCompat.METADATA_KEY_DISPLAY_ICON`

Fallback: `R.mipmap.ic_launcher`.

## Progress Handling

WebView sends position/duration every throttled state push:

```js
const posMs = Math.round((cur || 0) * 1000);
const durMs = Math.round((dur || 0) * 1000);
```

Service binds:

```java
int progress = durationMs == 0
        ? 0
        : (int) Math.min(1000, positionMs * 1000 / durationMs);
views.setProgressBar(progressId, 1000, progress, false);
views.setTextViewText(timeId, formatTime(positionMs));
views.setTextViewText(durationId, formatTime(durationMs));
```

Same position/duration also updates `PlaybackStateCompat` for lockscreen/system controls.

## Playing / Paused / Dismiss

Notification state comes only from WebView `isPlaying`:

```java
.setOngoing(playing)
```

Playing:

```text
setOngoing(true)
```

Paused:

```text
setOngoing(false)
```

Paused notification dismissal does not call `stopSelf()`, does not stop WebView playback, and does not release MediaSession. Service stays `START_STICKY`. MediaSession release occurs only in `onDestroy()`.
